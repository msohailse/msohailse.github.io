A local job-search dashboard, feature by feature

Muhammad Sohail · 27 Sep 2026 · 4 min read

I run my whole job search from a dashboard on localhost — it started as a fork of an open-source job tracker that I’ve reshaped around how I actually apply. No cloud, no account, no “we’ll email you”. One Python process and a SQLite file on port 8765. This round of work was about honest numbers and a daily habit you’ll actually keep.

What’s in it at a glance

  • A daily goal of 5 applications, with a streak counter and time-to-goal.
  • Real outcome tracking (interviewing / offer / rejected / no deal) that keeps your applied history honest.
  • A report tab: pipeline, success ratio per stage, day-by-day applications.
  • One-click skills analysis across every job scoring 7+.
  • LLM key-concept highlights, saved on each job card.
  • Resume variants (Italy / Norway) that flow through resumes, cover letters, and the public PDF links on my site.
  • Tailored resume and cover letter per job, with optional extra instructions.
  • Tagged todos and a read-only Gmail inbox view.

Daily goal, streaks, and time-to-goal

A slim HUD sits at the top of the dashboard: 4 / 5 with a progress bar, a streak counter, and your best streak. Hit the fifth application and it throws confetti and reports how long it took — from the first application of the day to the one that finished the goal. Today: 1h 46m.

The count includes every application made that day, regardless of how it later resolves, so logging an interview next week doesn’t erase the fact that you applied. The streak counts consecutive days that hit 5; today stays “in progress” until it’s done, so an unfinished morning doesn’t break the run.

Tracking that stays honest

The old toggle was applied / not-applied, which stops being useful a few weeks in. Now each job moves through real stages. Two rules I refused to compromise on:

  • A rejection doesn’t erase the application. The date stays, so history stays true.
  • “Stale” jobs (gone from the board, but I did apply) are kept and hidden from the active list, never deleted. Deleting them would quietly inflate my success rate.

Report tab

Pipeline counts, success ratio at each stage, and a day-by-day breakdown of applications. The headline number is “applications sent” and nothing else — no vanity metrics, no invented score.

Skills analysis

One button reads every job scoring 7+ and writes a consolidated list of what the market keeps asking for, plus where my gaps are. It’s a market view, not a per-job one, and it’s saved so I can re-read it before a batch of applications.

Highlights and cover letters

Highlight a job and an LLM pulls out the key concepts as chips on the card. Cover letters generate from the description, and you can add extra instructions first (“lead with the platform work, skip the frontend bullets”). The same works for the tailored resume.

Resumes: tailored per job, variant per country

I keep two versions of my resume — one for Italy (Italian phone, Florence) and one for Norway. A dropdown picks the variant, and it flows through resume generation, cover letters, and the public PDF links on my site. Adding a third country is a single command.

Files download properly instead of opening a raw path, they get filed under downloads/, and deleting one is a click on the file itself with a confirmation — not a blunt “remove everything”.

Todos and inbox

Todos are tagged, so I filter them by context. Inbox insights connect (read-only) to Gmail and surface recruiter replies against the matching job.

What I learned building it

The unglamorous parts mattered most. Cleaning up the apply URLs — the scraper had stored the literal string "None" for 369 jobs, so the Apply button pointed at localhost/None — did more for the tool than any new button. Keeping rejected and stale jobs in the data instead of deleting them is what makes the success rate worth trusting. And the hardest feature to build wasn’t technical at all: it was the streak, because it’s the only thing that gets me to open the dashboard on a bad day.

If you’re in a long search, build the smallest dashboard that mirrors your real workflow, and make one number on it honest. The rest follows.
